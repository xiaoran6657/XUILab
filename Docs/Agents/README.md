# XUILab Agent 工作流

设计日期：2026-09-05。适用范围：XUILab 的 M0–M4 实现、验证、性能实验和成果整理。

项目目标是把 ListView、程序化渐变与过渡、自动性能测试转化为可解释、可复现的展示材料，同时训练性能分析能力。Agent 负责工程推进；用户在目标决策、必要的编辑器操作和成果确认时参与。

## 已确定的边界

- 需求依据：[项目分析](../PROJECT_ANALYSIS.md)与[路线图](../MVP/ROADMAP.md)。路线图负责“做什么”，本目录负责“如何协作和证明完成”。
- 仓库根为 `<repo>`；Unity 工程根为 `<repo>/XUILab`。路线图中的 `UnityProject/` 是早期建议目录，实际执行使用 `XUILab/`。
- Unity 固定为 `2022.3.45f1c1`，当前 URP `14.0.11`、UGUI `1.0.0`、TMP `3.0.9`。具体事实和未验收事项见[环境快照](ENVIRONMENT_BASELINE.md)。
- 当前 MCP 使用用户提供的 stdio 连接；一次只由一位明确的 Unity 操作者使用。需要多 Agent 时优先拆分源码审查、实验设计、离线数据分析。
- 当前请求仅设计工作流。本文、模板和待办建议不代表已经启动 M0、不代表已经取得运行或性能证据。

## 最小执行方式

默认一个主 Agent 兼任协调和实现角色，持续完成用户已授权的任务或阶段。小型文档工作可以自行检查；涉及组件生命周期、程序集、场景集成或正式性能结论时，安排独立复核。角色并不等于必须新建一个用户可见任务。

只有用户或适用的 `AGENTS.md`／技能明确要求子 Agent 时才委派。未获委派授权时，主 Agent 可以完成实现和自检，但不能把自检写成独立审查；需要的独立验收保留为待完成项。用户可以直接使用[启动提示词](START_PROMPTS.md)授权一次完整的任务闭环。

`Docs/Agents/` 是工作流文档，不会因为目录名而被 Codex 自动加载。当前通过启动提示词显式引用；将来若增加根目录 `AGENTS.md`，只需提供简短入口和适用范围，不应复制整套正文。Codex 的自动指令发现使用约定的文件名与目录层级。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 首次实施时的切入点

从 M0-01 的剩余验收开始，承认用户已完成创建工程和 MCP 接入。先检查 Git 忽略、依赖锁定、目录和基线，再建立最小 Runner 闭环；不用重新创建 Unity 工程。

当前仓库没有首个提交；根目录已建立 Unity／IDE 生成内容的忽略规则和文本／二进制属性。实施 Agent 仍应在首次提交前核对实际跟踪范围，避免把生成文件或未经处理的实习参考材料纳入提交／公开成果。不要直接执行 `git add .`。

本目录提供规则和模板；实际任务记录在获得执行授权后按 [PM 合同](PM_CONTRACT.md)创建。不要把空模板当作已执行记录。
