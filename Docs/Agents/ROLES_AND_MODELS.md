# 角色、独立性与模型

## 角色合同

| 角色 | 负责 | 不应做 |
| --- | --- | --- |
| 主 Agent／Coordinator | 理解授权、维护 Brief 和 PM、依赖调度、资源占用、汇总验收 | 把子 Agent 的完成消息直接等同于验收通过 |
| Implementer | 在约定范围实现、针对性自检、交付候选身份和 Handoff | 用修改验收条件掩盖失败 |
| Reviewer | 从合同、代码和原始证据独立检查正确性、范围、证据关联 | 直接修补被审代码后仍自称独立审查 |
| Validator | 制定／执行验证、区分未运行与失败、保存可追溯结果 | 把截图、工具 success 或进程启动当成测试完成 |
| Unity Operator | 在独占时段执行编辑器操作，记录前后状态 | 在另一个 Agent 正在采样时切场景、编译或采集重型诊断 |
| 用户 | 目标与范围决策、必要的人工操作、未授权的发布等确认 | 代替 Agent 做可自动完成的重复检查 |

主 Agent 可以兼任 Implementer 和 Unity Operator。R2 默认另设一位独立复核者兼任 Reviewer／Validator，以控制协作成本。Runner 的判定逻辑、统计协议和对外性能结论若存在较大争议，再拆成独立审查与独立验证两位；这仍需符合当前会话的委派授权。

## 什么才算独立

独立复核者不得是该候选的实现者，应从 Brief、实际候选和原始证据重新检查，而不只复述实现者摘要。使用另一个模型不是独立性的必要条件；同一个 Agent 换一个“Reviewer”标题也不会获得独立性。

报告分别记录 `review_independence` 与 `execution_independence`：

- 独立 Agent 审阅代码和日志，但由原实现者操作 Unity：独立审查成立，独立执行不成立。
- 独立 Validator 在交接后取得唯一操作权并重新运行：可以标记独立执行。
- 所有工作都由主 Agent 完成：标记 self-check，保留 required 的独立复核待办。

Reviewer 可以提出补充验证，由单一 Unity Operator 执行后交回原始证据。普通 R2 不强制独立操作编辑器，但需要真实独立地核对验证方法和证据。Brief 若明确要求独立复跑，就不能用上述方式替代。

## 模型选择建议

以下是面向本项目的建议，不是自动修改模型配置的指令。默认保持当前任务／用户配置；显式指定模型时，以当前工具支持、账号可用性和用户选择为准。模型列表和推理档位会变化，使用时重新核对。

| 工作 | 可选配置 | 使用理由 |
| --- | --- | --- |
| 任务拆解、复杂生命周期、性能归因、重要复核 | `gpt-5.6-sol`，必要时 high | 问题存在多步推理与取舍 |
| 合同清楚的组件实现、测试、日常复核 | `gpt-5.6-terra`，从默认／medium 开始 | 平衡实现能力、时延与成本 |
| 文件盘点、链接检查、固定格式整理、窄范围检索 | `gpt-5.6-luna`，默认或 low／medium | 输入输出明确、结果容易机械核对 |

不统一使用 max。先改善上下文、验收标准和工具证据，再考虑提高推理强度。独立复核的能力应匹配问题复杂度，不能仅因为“只读”就一律选最便宜配置。上述分工由项目需求推导，能力定位与推理成本取舍参考 [OpenAI 模型文档](https://learn.chatgpt.com/docs/models)。

分派时提供目标、输入、允许写入范围、验收条件、禁止操作和返回格式。缺省子 Agent 会继承配置，模型与推理配置应按实际客户端能力设置；不要声称已经切换却没有调用或确认。[官方子 Agent 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)

报告分别填写“请求的配置”和“实际可观察配置”；无法读取时写 unknown，不从角色名推断。模型不可用时保持已有可用配置并记录差异；若用户把特定模型定为验收条件，先说明限制，不静默替换。
