## 最先记住的三件事

1. 功能正确、测量有效、性能改善是三种判断。少更新了一行但显示旧数据，不算优化成功。
2. 工作次数、函数耗时、整帧间隔是三种量。9次Bind减到1次不能推出9倍帧率；顶点减少也不能直接推出GPU更快。
3. 原始实验有明确版本与环境。M3探索报告仍保持当时dirty身份；后续干净构建通过测试，不能把旧数据改成新提交的正式性能证据。

## 当前材料完成到哪里

列表与渐变已有实现、测试、原始实验和分析。现有列表trace是Editor探针记录的事件/计数，**不是CPU Timeline性能捕获**；当前报告中的CPU、GC、内存和部分UI/GPU指标为unavailable。[Profiler篇](PROFILER_GUIDE.md)给出实际trace阅读和后续捕获方法，未把操作教程写成已采集结果。

## 把文档发给Agent时

可以复制下面的请求，并附上不理解的章节：

> 请解释XUILab的Docs/Learn中的这段内容。我基础较弱，请先解释术语，再用一个小例子解释原因。请读取本篇链接到的实际源码和实验记录，以文件名+方法/字段定位；明确区分源码推断、真实观测和缺失证据。不要自动改代码、启动Unity或复跑实验。若证据链接不可访问，告诉我缺哪个文件及它在EVIDENCE_NAVIGATION.md中的归档入口，不要补造数据。

Agent阅读路线：本篇 → 用户疑问对应的专题 → 该节源码symbol → 测试或原始数据 → 原报告限制。文件链接使用仓库相对路径，复制整个仓库仍可解析；单独发送Markdown到无法访问仓库的服务时，相对链接不会携带文件内容，需要另外提供被引用文件。
