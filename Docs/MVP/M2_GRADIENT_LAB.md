## 1. 主题与目标

实现一个独立、可测试的 UGUI 程序化渐变组件和确定性过渡控制器，展示四顶点线性插值的边界、非线性曲线为何需要更多采样，以及网格质量、Canvas 重建和渲染成本之间的取舍。

实现依据来自 LUIImage 材料，但新组件不依赖完整 LUI 基类。成果明确标为个人复现／后续改进，不声称复制了原项目完整实现或历史性能。

## 2. 阶段成果

- 冻结的颜色、方向、bias／position、alpha、颜色空间和降级合同。
- 可挂在 UGUI Graphic／Image 上的 GradientEffect，以及与 Mesh 逻辑分离的 GradientTransitionController。
- 四顶点线性路径、固定 32 段非线性路径、顶点通道保留和安全回退。
- 数值、网格、截图和 Player 性能四类证据。
- 静态／动态、单图／网格／裁剪列表的代表矩阵及第二组展示草稿。
- 对细分、色带、合批和重建成本的学习复盘。

## 4. M2-01：冻结语义

Task Brief 在写 Mesh 代码前回答：

- `direction` 是水平、垂直或后续可扩展轴；起点和终点颜色如何映射。
- base Graphic color／texture alpha 与渐变色如何相乘；在 Linear／Gamma 色彩空间中在哪个空间插值。
- `bias`／`gradientPosition` 表示中心颜色比例还是几何过渡位置。选择一种数学定义并用公式、端点和中心样例固定，不能靠变量名含混表达。
- 合法范围、极端值、退化尺寸、透明颜色、禁用状态和相同值重复赋值的行为。
- 哪些 Image Type 和输入网格支持非线性细分，哪些只在现有顶点上着色或关闭效果。
- 过渡的 start/end 参数、duration、clock、easing、restart／interrupt／cancel、disable／reuse 后状态。

推荐把“颜色函数”和“网格采样”分开：纯函数 `Evaluate(t)` 产生规范颜色，线性路径仅使用端点；非线性路径按几何位置采样它。M3 自适应细分复用同一函数，避免改变视觉语义。

## 5. 支持与降级矩阵

| 输入 | 线性顶点着色 | 非线性细分 | 最低行为 |
| --- | --- | --- | --- |
| Simple 严格矩形 4 顶点／6 索引 | 支持 | 固定 32 段 | 完整合同 |
| Preserve Aspect 后仍为合法矩形 | 支持 | 通过几何检查后支持 | 以实际绘制矩形归一化 |
| Sliced／Tiled | 支持现有顶点着色 | 首期不重建拓扑 | 明确近似质量，不破坏原拓扑 |
| Filled／Radial 或任意网格 | 按实际顶点着色 | 首期不重建拓扑 | 不假设顶点顺序，不越界 |
| 退化宽／高、空 Mesh | 安全返回 | 禁止细分 | 无 NaN、异常或非法索引 |

“严格矩形”需要位置、UV 和三角形拓扑检查，而不是只判断 `vertexCount == 4`。回退路径必须记录实际模式，展示和报告不能把近似效果称作完整 32 段曲线。

## 6. M2-02：实现合同

### GradientEffect

- 继承适合 UGUI 生命周期的 Mesh effect；运行时不引用 Editor。
- 参数 setter 先比较实际变化，再触发相应 vertex dirty；序列化校验不会在每帧反复标脏。
- 线性路径不改变拓扑。非线性矩形按方向生成 32 个 segment，即 33 个采样截面；实际 vertex/index 数以实现结构测试固定，不只靠文档预估。
- 新顶点插值并保留 position、normal、tangent、color、uv0–uv3 等所需通道；颜色统一由合同函数产生。
- 使用复用缓冲或 VertexHelper 合理路径；正式目标是在稳态或持续变化时无意外托管分配，不能先写“零 GC”再寻找证据。
- 不修改共享材质，不为每个实例创建材质副本。

### GradientTransitionController

Controller 只推进规范化 progress 并设置参数，不拥有 Mesh 生成。Runner 可直接注入 progress，使 A/B 动作与帧率无关。交互演示可选择 scaled 或 unscaled time，但合同固定；duration≤0、重复启动、打断、反向、禁用、销毁和池复用均有明确终态。

不要求引入第三方 Tween 库。若后续使用，需证明依赖必要性、取消／复用语义和测量中的额外成本。

## 7. M2-03：质量验证

| 检查 | 方法 | 通过边界 |
| --- | --- | --- |
| 数学端点／中心／单调性 | EditMode 纯函数样例与参数化测试 | 与冻结公式及容差一致 |
| 网格拓扑 | 输入／输出顶点、索引、边界、三角形方向检查 | 无越界、裂缝、NaN、退化意外 |
| 通道保留 | 使用非默认 uv1–uv3、normal、tangent 的测试顶点 | 插值或复制符合合同 |
| Image Type 降级 | Simple、Sliced、Tiled、Filled／Radial 场景 | 模式和报告与矩阵一致 |
| 视觉参考 | 固定分辨率、颜色空间和参数生成参考图／截图 | 数值和像素误差在预定容差 |
| Shader 输出 | 至少一个读取附加通道的受控材质 | 细分前后语义保持 |
| 过渡生命周期 | 启动、打断、取消、disable／reuse、结束 | 没有旧动画回写或悬挂状态 |

图片比较先固定截图区域、分辨率、抗锯齿、颜色空间和容差。视觉检查补充数值测试，不能由单张“看起来正确”的截图替代。

## 8. M2-04：实验矩阵

| 维度 | MVP 覆盖 |
| --- | --- |
| 状态 | Image only、Effect disabled、Linear static、Nonlinear static、相同值重复赋值、持续 transition |
| 布局 | 单张大图、可见 Grid、RectMask2D 裁剪列表 |
| 动态比例 | 少量元素变化、全部可见元素变化；动静分 Canvas 的代表对照 |
| 规模 | 100、500、1000；流程有效后 2000／5000 压力档 |
| 参数 | 两个方向、代表 bias、极端 bias、透明度；不默认执行全笛卡尔积 |
| 质量 | 曲线采样误差、截图误差、实际 segment／vertex／triangle |
| 成本 | dirty／rebuild 次数、CPU／UI marker、帧间隔、GC、vertices、Draw Calls／Batches；GPU 按能力记录 |

每轮记录生成数量、实际可见数量和被裁剪数量；“生成 5000”不能写成“同时渲染 5000”。Static no component work 不等于 no render cost。批次不增加只支持该场景下的批次结论，不能扩写为零成本。

## 9. 出口门槛

- 数学、拓扑、通道、Image Type 降级和 transition 生命周期 required Case 通过。
- 静态与动态至少各有一组有效 Windows Player 对照；质量和性能数据对应同一冻结语义。
- 报告能够解释顶点增加、Canvas rebuild、材质／纹理／裁剪和 batches 的关系。
- 相同值重复赋值不会由组件主动持续 dirty；动态场景的工作量和可见数明确。
- 第二组说明图和视频草稿存在，标明参数、fallback 和正式 run-id。

学习检查：解释四顶点为何不能表达一般非线性曲线、细分成本发生在哪里，以及更密网格为何不必然消除颜色量化色带。

## 10. 风险与停止条件

- 曲线语义无法从历史材料唯一恢复：选择并记录新项目合同，标为个人复现，不拖延实现等待不存在的原件。
- 附加通道或 Shader 不可验证：默认 UGUI 视觉仍可推进，但相关兼容结论保持 not_run，M2 出口按 required 定义处理。
- 5000 压力档不可运行：保存失败和共同规模，避免为完成矩阵降低质量。
- Canvas 重建掩盖纯 Mesh 成本：增加诊断运行或隔离 Canvas，仍以代表场景总成本为主要用户体验证据。
