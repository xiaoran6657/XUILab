# Gradient 矩阵超时恢复补充 r1

本补充在原 gradient-matrix-r5 的2000项全量动态第1次独立运行触及180秒之后、任何续跑之前冻结。原计划130个run-id、顺序、构建、300帧预热/1800帧采样、阈值与超时预算完全保留，不重新编号或重发失败run。

已完成23项有真实0退出码与逐run校验回执；2000all-r1由launcher只终止自有PID58164，耗时180.094秒、exit1并保留日志/失败sidecar，剩余106项未派发。恢复不是把原计划改为全通过。

## 预先固定的恢复规则

1. 已有成功回执必须重验原始数据和plan/build/identity/quality绑定；不重新运行。
2. 存在intent但无确定终态、输出但无receipt、非超时失败、矛盾记录或未知文件时立即停止，不能跳过不确定操作。
3. 已证实终止的wall-clock timeout保留；同一case尚未运行的后续重复写deferred记录，引用原失败run-id及其SHA。延期不产生假样本，不算通过。
4. 其他case严格按原顺序继续。5000all仍执行其原计划第一次尝试；若同样超时，其余重复延期。不提高180秒上限，不降低采样帧数，不修改画质。
5. 新进程仍用仓库级唯一锁、不可覆盖intent、确切自有PID、终态退出码与原始证据校验。新的恢复工具源码SHA绑定到resume-policy及新回执；它是构建后增加的编排工具，不声称参与了原r5 Player构建。
6. 最终完整计划保持partial/timeout/deferred事实，绝不使用原all-pass verifier宣称130次通过。仅当某组原定5次全部有效时才进入该组重复统计与A/B；压力失败和延期在同一报告显著列出，没有用零值补样或隐去失败。

恢复没有改变视觉/质量、统计或有效性判据。若因同一case超时而少于5次，不能报告该组稳定性能比较；可以报告其执行边界。原计划及所有成功/失败产物保持原路径和内容。
