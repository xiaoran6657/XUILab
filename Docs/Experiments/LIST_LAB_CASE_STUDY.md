# List Lab 案例草稿

本项目独立实现固定行高窗口，底层使用现有 Unity UGUI；未导入 LoopScrollRect，也未复制参考材料中的公司 Runtime 代码。来源与许可边界见 [List 合同](LIST_CONTRACT.md)，当前测量结果见 [Player 实验报告](LIST_BENCHMARK_RESULTS.md)。

## 问题与实现

同一份模拟排行榜需要支持普通 ScrollRect 与虚拟列表。公平基线共用 Cell 工厂、字体、Binder、固定行高 LayoutGroup、RectMask2D 和 Canvas；普通列表装载 N 个对象后滚动，虚拟列表只保留可见窗口与预取范围。两者没有在普通滚动路径故意加入 Instantiate/Destroy。

384 px 视口可容纳 8 个 48 px 完整行；存在部分行时最多涉及 9 行，加上上下各 2 行预取，最多租赁 13 个 Cell。这个预算由几何合同推导，不是历史材料中的固定 `cellMax=8`。单模板缓存最多 16 个，双模板分别维护；数据集合大小与场景对象数量是不同指标。

## 池归还错误及保护

只用 Stack 存储空闲 Cell，无法阻止同一对象被重复 Return。重复引用随后可能被连续 Rent 给两个条目，造成内容互相覆盖和数量诊断失真。

本实现分别登记 owned、leased 和模板 cache：Return 先验证唯一归属和当前租赁，再 Unbind、停用并缓存；未知、重复或失效对象返回 false 并增加拒绝计数，不进入缓存。外部销毁通知和 Sweep 负责收敛失效引用。实例恒等式为 `unique = leased + cached = created - destroyed`，同时验证 Bind/Unbind、模板和 item ID。

活跃计数由独立的 `ListCellActivity` OnEnable/OnDisable 回调维护，避免把“租出”当作“实际处于 hierarchy active”。动画组件会自行禁用，因此它不能承担活跃计数。采样路径不会为普通列表每帧扫描全部 N 个对象来获得 active 数量。

## 布局与动画冲突

若 LayoutGroup 和动画同时写 Cell 的位置或缩放，下一次布局会覆盖动画，复用又可能把旧过渡带给新条目。现在 LayoutGroup 只管理外层 Cell；动画写内层 Wrapper。Unbind 重置 scale、alpha、position、文字与未完成过渡，Rebind 先验证输入再解除旧绑定。

同理，实际可见矩形必须在布局完成后读取。基准在下一帧核对前一动作的实际行矩形与可见交集；展示诊断先完成布局再读取，避免界面显示待布局的计数。诊断刷新、双模板、渐隐与动画均不进入主单模板基准。

## 位置恢复与剩余成本

位置保存 stable item ID、fallback index 和行内像素 offset。恢复先找同一 ID，缺失时按索引回退并夹紧范围；空数据回到顶部；恢复同时清除 ScrollRect 惯性。覆盖相同数据、重排、条目移除、缩短、首尾和小数 offset，容差固定为 0.05 px。

虚拟化减少 Cell 对象、布局和渲染准备的工作量，但没有消除数据工作。生成、复制和校验 N 个条目仍是 O(N)，stable ID 恢复目前线性查找。普通列表冷开、清空和重填也需要处理 N 个对象；缓存上限意味着其生命周期重开可以重建大量 Cell。下一阶段若优化索引或单项刷新，应另立对照，不能把尚未完成的 M3 工作算进 M1 收益。

当前 `RefreshItem` 保留刷新可见窗口的基线语义，供 M3 真正单项刷新比较。帧间隔、首次可交互、对象数量和内存是不同指标；缺失的 Profiler 指标写 unavailable，Bind 数量不能替代 mesh rebuild 数量，对象计数收敛也不能单独证明原生内存无泄漏。

虚拟窗口还有自身开销：窗口变化需要重新绑定复用 Cell 并更新布局，普通列表在装载后可以只移动 Content。本协议在相同帧数内遍历全量范围，N 越大时单帧跨过的行数也越多；10000 压力档不能当作日常拖动速度。是否改善某个分位数要由同一显示环境的实测回答，不能从“大量减少对象”直接推出所有性能指标都改善。

## 演示与证据使用

30 秒草稿依次展示普通列表、虚拟窗口、双模板/渐隐、保存恢复和重开。实时诊断用于说明机制，不是性能样本。正式动作由确定性 C# Runner 驱动，采样外导出；图片、视频和编码使用独立进程阶段。

隐藏窗口曾导出黑帧，因此相关旧数据被明确排除。可见窗口重采样使用新身份，并保留旧产物与恢复记录。M1 是未提交候选的工程探索；作品集公开数字须在 M4 获得授权后，针对干净提交重新构建和验证。
